1. Why this document exists
The PRD defines the product. This blueprint defines the smallest coherent demonstration of it. It combines the screen inventory, scripted data, happy path, and acceptance checklist so the team does not create separate wireframe specifications, data dictionaries, demo scripts, and content matrices before they are needed.
SCOPE RECOMMENDATION Build one complete loop deeply, then represent the rest through credible secondary states. The primary loop should be: journey signal -> panel -> study -> activation brief -> predicted vs actual -> approved persona update.

3. Fictional demo scenario
A generic company is improving the digital decision journey for a new service bundle. A real-time journey alert shows that customers are pausing at the plan-comparison moment. The team wants to test two message approaches before a broader campaign: "More control" versus "Everything made simple."
3.1 Scripted hypothesis
HYPOTHESIS Customers with high need for control will prefer the Control message, while time-poor and reassurance-oriented customers will prefer the Simplicity message. A transparent comparison should outperform either message alone for evidence-driven and value-focused audiences.

3.2 Scripted outcome
The study recommends a segmented treatment: Control for Avery, Guided Simplicity for Riley and Quinn, Transparent Value for Morgan and Taylor, and Effortless Continuity for Cameron. The campaign simulation predicts stronger completion than the current generic message. Actual results later support most of the prediction but show that Taylor responded better than expected when the message included source transparency. The system proposes a small increase in Taylor's responsiveness to evidence-backed personalization, which the steward approves.

11. Acceptance checklist
☐ All six personas have coherent content across card, detail, chat, panel, study, and learning states.
☐ The difference among observed, inferred, and predicted information is visible.
☐ The panel shows individual voices before synthesis.
☐ The study contains a decision, stimuli, method, measures, findings, limitations, and recommendation.
☐ Journey, study, activation, and learning objects share persistent IDs.
☐ Predicted and actual metrics reconcile mathematically and narratively.
☐ The persona update changes only one dynamic trait and records why.
☐ No client, bank, product-vendor, or regulated-industry language remains.
☐ Every synthetic metric and persona is labeled illustrative or fictional in an appropriate location.
☐ The demo can be reset and replayed without stale state.
12. Build sequencing
Create the data model and synthetic content first.
Build the global shell and route structure.
Implement persona catalog/detail and journey alert.
Implement panel and scripted moderator synthesis.
Implement study setup and findings.
Implement activation brief and learning loop.
Add governance cues, evidence drawers, versioning, and reset.
Perform narrative QA using the happy-path script, then visual and accessibility QA.
13. Scope change rule
RULE A new screen or feature enters MVP only if it is required to complete the primary closed loop or removes a credibility gap in that loop. Otherwise add it to a post-demo backlog.
